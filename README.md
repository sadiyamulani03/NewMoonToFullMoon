# NewMoonToFullMoon

Midnight Network Builder Challenge — Levels 1 & 2.

- **Level 1** (`level1/`) — a private-by-default **counter** Compact contract with a deliberate `disclose()` path.
- **Level 2** (`level2/`) — **MidnightTrace**, a browser dApp that connects your wallet and proves a private forensic step on-chain.

> Live Level 2 demo: **https://midnighttrace.vercel.app**

## Project structure

- `level1/` - Midnight Compact contract application
  - `contracts/counter.compact` - the counter contract (public ledger + private witness + deliberate `disclose()`)
  - `contracts/hello-world.compact` - the starter hello-world contract
  - `contracts/managed/` - compiled contract artifacts and keys (generated by `compact compile`)
  - `tests/` - offline unit tests for the counter contract (`counter.test.ts`)
  - `src/` - deployment, CLI, wallet, and network scripts
  - `docker-compose.yml` - local devnet / proof-server services
- `level2/` - MidnightTrace, the Level 2 frontend dApp
  - `src/` - React + Vite + TypeScript dApp (wallet hook, providers, circuit UI)
  - `src/contract/compiled/counter/` - compiled ZK assets (prover/verifier keys, ZKIR) served statically
  - `tests/` - build & asset smoke test
  - `vercel.json` / `netlify.toml` - hosting config (live on Vercel)


## Contract behavior

The `counter.compact` contract maintains public ledger state (`total` counter and
`lastDisclosed`) while taking a private witness (`amount`) as a circuit input.
`increment(amount)` proves `total' = total + amount` without placing `amount`
on-chain; `incrementAndReveal(amount)` does the same but deliberately writes
`amount` into public `lastDisclosed` via `disclose()`. The starter
`hello-world.compact` contract works the same way: its `storeMessage` input is a
private witness that only becomes public when the contract calls
`disclose(customMessage)`. Full public/private breakdown lives in
`level1/README.md`.

# Level 2 — MidnightTrace (frontend dApp)

MidnightTrace is the Level 2 web frontend: a privacy-first "blockchain
forensics" tool. It connects your wallet, joins the Level 1 counter contract on
Preprod, and calls the `increment` circuit with a **private witness amount** —
proving `total' = total + amount` on-chain without ever revealing `amount`.

## Live Demo

**https://midnighttrace.vercel.app**

## Deployed contract (counter — used by level 2)

| Network  | Address |
|----------|---------|

## What it does

1. Connect your Midnight wallet (1AM or Lace) on **Preprod**.
2. The dApp joins the deployed `counter` contract on-chain.
3. Press **Run the circuit** — `increment(amount)` is called with a private
   witness `amount`. A zero-knowledge proof is generated locally (delegated to
   the wallet), the transaction is balanced and submitted.
4. The public ledger `total` increases on-chain, while the hidden `amount` is
   never placed on-chain and never appears in the UI.

## Privacy model

- **Public:** `ledger total` (updates with every call); `ledger lastDisclosed`
  (only when a caller deliberately uses `incrementAndReveal`).
- **Private:** the `amount` witness — it exists only inside the ZK proof.
- **Proven without revealing:** that `total' = total + amount` for the hidden
  `amount`, without the network or anyone else learning `amount`.
- **Privacy claim:** an on-chain observer sees a valid proof that the counter
  moved, but cannot see by how much. A fork-and-diff against
  `incrementAndReveal` proves the difference: the reveal path writes the amount
  to `lastDisclosed`, the private path leaves it nowhere on-chain.

## Tech stack

- React 19 + Vite 7 + TypeScript
- `@midnight-ntwrk/midnight-js` 4.1.1 (indexer public data provider, level
  private state provider, fetch ZK config provider, ledger-v8)
- DApp Connector API (`@midnight-ntwrk/dapp-connector-api` 4.0.1)
- Wallet-delegated proving (1AM / Lace); indexer queries use the public
  Preprod indexer (no API key required)
- Vercel (production hosting)
