## What We Heard (Themes)

Themes are grouped by how many independent users mentioned them. No single suggestion is presented as a majority request unless it recurred. The two Mustafa responses are counted as one user's perspective for detailed UI feedback (see below) to avoid inflating counts.

### Strongest Positive Themes (most mentioned)

* **Audit / audit verification** — the most recurring liked feature (Audit page, Audit window, Audit verification, forensic verification). Liked for making verification easy to understand.
* **Privacy / privacy-focused approach** — recurring (privacy concept, privacy-first approach, privacy of forensic evidence).
* **ZK proof concept / proof workflow** — recurring (ZK proof concept, proof workflow, proof verification, proving without exposing underlying evidence).
* **Dashboard** — recurring liked surface.
* **Case creation / case management** — liked for simplicity.
* **Simple / clean interface and interactive UI** — recurring (simple UI, clean design, clean interface, interactive UI).
* **Ability to verify without exposing underlying evidence & immutable forensic trail** — explicitly praised by Zeel Chauhan, Fajrin, Samara, Rashi Achaliya, Purva Pawar.

### Repeated Improvement Themes (mentioned by more than one user)

These were requested by multiple independent users, each at modest frequency (2–4 mentions). They are not presented as "all users requested":

* **Transaction / proof progress indicators** — Sanskruti Chavan, Purva Pawar, Sofiya Quraishi, Arya Bhagat, Jorge Soares, Amitabh Dey (various phrasings: progress indicator, proof-generation progress, transaction progress).
* **Clear transaction / proof status & "Proof confirmed" state** — Gayatri Panickar, Alicia Nadar, Amitabh Dey, Jorge Soares, Rashi Achaliya (clearer status / wasn't sure transaction completed).
* **Faster transaction / proof processing** — Tanishq Sonawane, Sanskruti Chavan, Purva Pawar, Auron (noted as chain/proving time, not a UI bug).
* **Better wallet connection status & timeout handling** — Anjali Ram Parde, Purva Pawar, Mustafa Berke Bakır (connection took seconds / timeout prevented testing).
* **Clearer first-time-user instructions** — Purva Pawar.
* **Tooltips for technical terminology** — Sakshi Manikari.
* **More explanation of ZK proofs / how verification works** — Sheetal Goud, Debansh Tiwari.
* **Audit search / filter by case ID** — Zeel Chauhan, Samara (2 requests).
* **Landing page, privacy explanation on first screen, simplified documentation** — Anam Pathan, Rashi Achaliya, Khushi Nagare (one each).
* **Better UI/UX generally** — Anushka Kachare (one explicit request).

### Detailed UI/UX Feedback — Mustafa Berke Bakır (2 responses, 2026-08-17)

One user (Mustafa Berke Bakır) submitted two responses with the same detailed suggestions. To avoid inflating counts, this is treated as **one user's detailed perspective** with many items:

* Complete localization/translation (UI mixed English/Turkish — likely browser auto-translation)
* Proper loading indicators and error toasts
* Reduce harsh dense horizontal stripe background / improve readability and text contrast
* Add intuitive icons, status badges and network indicators
* Remove duplicate wallet connection buttons
* Add timeout detection and user-friendly fallback states for failed RPC/wallet connections

These are legitimate UX items and were addressed (see What We Changed), but they are not counted as 11 independent requests.

### Bugs / Friction (reported)

* **Wallet connection timeout / few seconds to connect** — Mustafa (timeout prevented testing), Purva Pawar (took a few seconds), Anjali (status unclear). Midnight wallets require a desktop extension; mobile and RPC issues were addressed with status messages and fallbacks.
* **Proof generation / transaction took a while** — Sanskruti Chavan, Tanishq Sonawane, Auron, Purva Pawar. This is proving + chain finalization time; progress indicators were added.
* **Terminology unclear** — Sakshi Manikari (one mention).
* **No 2/5 or 1/5 ratings; no fabricated bugs.** All other respondents reported "No" / "No bugs" / "Nothing" / "Nopes" or left the field blank.
